# 迟滞回线（状态机）模式策略分析

## 1. 执行摘要 (Executive Summary)
针对 15 分钟 Polymarket 套利策略，引入 **迟滞回线机制（状态机）** 是非常可行且强烈推荐的。它解决了关键的“信号闪烁”（Whipsaw）问题，即评分在单一阈值附近徘徊（例如在 79 和 81 之间反复跳动），导致不必要的频繁开仓/平仓循环和滑点损失。

通过引入一个“缓冲区”（65-80 分），系统获得了稳定性，能够在过滤微小噪音的同时更长久地持有趋势。然而，考虑到 15 分钟市场的生命周期极短，**必须** 引入 **延迟保护（方向锁定）**，以防止在剧烈反转期间退出过晚。

## 2. 核心逻辑架构 (Core Logic Architecture)

### 2.1 状态定义 (State Definitions)
*   **`IDLE` (观望/空仓模式)**：默认状态。无持仓或持中立立场。
*   **`TRENDING` (活跃/持仓模式)**：确认已形成有效趋势。

### 2.2 转换规则（双阈值）(Transition Rules)

| 当前状态 | 条件 | 下一状态 | 动作 | 逻辑假设 |
| :--- | :--- | :--- | :--- | :--- |
| **`IDLE`** | 分数 < 80 | `IDLE` | 等待 (Wait) | 噪音 / 趋势形成中 |
| **`IDLE`** | **分数 >= 80** | `TRENDING` | **入场 / 发信号** | 强力突破 |
| **`TRENDING`** | 分数 >= 65 | `TRENDING` | 持有 (Hold) | 趋势延续 |
| **`TRENDING`** | **分数 < 65** | `IDLE` | **退出 / 停止** | 动能丧失 |

### 2.3 “死区” (The "Dead Zone": 65 ≤ 分数 < 80)
*   **行为**：系统“记住”了它之前的状态。
    *   如果是从 `IDLE` 上升而来，75 分 **不足以** 入场。
    *   如果是从 `TRENDING` 下降而来，75 分 **足以** 保持在场。
*   **收益**：消除了“抖动”。在单一阈值系统（例如 >80）中，分数跌到 78 再回升到 82 会触发“卖出 -> 买入”序列。但在迟滞机制下，系统会持续保持 `TRENDING` 状态，避免摩擦成本。

## 3. 关键增强与风险缓解 (Critical Enhancements)

### 3.1 “一票否决权”（方向锁定） - **至关重要**
由于 15 分钟市场的时间窗口极短，70 分在状态机看来可能在技术上是“安全”的，但价格可能正在崩盘。我们 **必须** 引入一个强制覆盖条件，无论分数如何都强制退出。

*   **逻辑**：
    ```go
    IF 当前状态 == TRENDING:
        IF 分数 < 65:
            切换至 IDLE (标准退出)
        ELSE IF (方向 == 看涨 AND 当前价格 < VWAP):
            切换至 IDLE (硬性否决 - 趋势破位)
        ELSE IF (方向 == 看跌 AND 当前价格 > VWAP):
            切换至 IDLE (硬性否决 - 趋势破位)
    ```
*   **理由**：分数（源自 RSI/MACD）是滞后指标。而价格相对于 VWAP 的位置是即时的。如果我们买涨，但价格跌破 VWAP，即使 RSI 还在 70 分冷却中，上涨逻辑也立即失效。

### 3.2 信号平滑 (Signal Smoothing)
*   用户建议预先对分数进行平滑处理（例如 SMA-3）。
*   **建议**：**谨慎使用**。
    *   **优点**：进一步减少噪音。
    *   **缺点**：增加延迟。在 15 分钟市场中，每一分钟都至关重要。
    *   **替代方案**：与其平滑输入的分数，不如依靠迟滞机制本身作为平滑器。15 分的宽阔缓冲区（65-80）本身就是一个强大的滤波器。如果确实要使用平滑，请保持 `N` 非常小（例如 SMA-2 或加权当前值）。

## 4. 实施计划 (Implementation Plan)

### 4.1 数据结构
在 `MarketState` 结构体或专用的 `PatternState` 映射中添加状态追踪器。

```go
type PatternEvaluator struct {
    State       string  // "IDLE" 或 "TRENDING"
    LastScore   float64 // 用于平滑（可选）
    EntryTime   time.Time // 用于分析持续时间
}
```

### 4.2 循环集成
在 `DetectPattern` 或特定的策略循环内部：

1.  **计算原始分数** (0-100)。
2.  (可选) 应用微小的平滑处理。
3.  **检查否决条件** (VWAP 破位)。如果触发否决 -> 强制 `IDLE`。
4.  **运行状态机更新**：
    *   根据 `CurrentState` 进入分支。
    *   应用 80/65 双阈值。
5.  **返回动作**：
    *   状态变更 `IDLE` -> `TRENDING`：**买入 (BUY)**。
    *   状态变更 `TRENDING` -> `IDLE`：**卖出 (SELL)**。
    *   状态未变：**持有/观望 (HOLD)**。

## 5. 潜在陷阱 (Potential Pitfalls)
*   **退出过晚**：如果市场垂直崩盘，RSI 可能会滞后。65 分的阈值可能触发太晚（例如价格已经跌了 5%）。**缓解措施**：“一票否决权”（VWAP 检查）解决了这个问题。
*   **错过再入场**：如果分数跌到 60（退出），然后反弹到 78，我们处于 `IDLE`。由于未达到 80，我们不会重新入场。这实际上是一个 **特性** 而非 Bug——它可以防止追逐疲软的反弹。

## 6. 结论
该逻辑是 **稳健且高度适用** 的。它将系统从一个“抖动的被动反应”机器人转变为具有信念的“趋势跟踪”系统。
